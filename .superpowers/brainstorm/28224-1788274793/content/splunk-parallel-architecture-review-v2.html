Architecture review · OCI Log Analytics + Splunk

Two delivery modes.
One governed detection catalog.

All supported sources land in Log Analytics for OCI-aware parsing, hunting, dashboards, and detections. Splunk receives either the raw parallel feed or a bounded, enriched evidence feed—without pretending a Log Analytics detection rule is itself a log forwarder.

DESIGN · TENANT-NEUTRAL

Supported operating modes

Customers may enable either mode—or both per source—while keeping ownership and cost visible.

01 Raw parallel fan-out

Reuse adibirzu/oci-splunk. Add approved OCI Logging sources to the Service Connector filter, send them to OCI Streaming, then consume with SOC4Kafka or Kafka Connect and land them through Splunk HEC.

flowchart TB S["OCI Audit · VCN · WAF · LB · custom OCI logs"] --> L["OCI Logging"] L --> C1["Connector A"] L --> C2["Connector B"] C1 --> LA["OCI Log Analytics"] C2 --> ST["OCI Streaming"] ST --> OS["oci-splunk consumer\nSOC4Kafka or Kafka Connect"] OS --> HEC["Splunk HEC · raw indexes"]
  • Best for mandated raw retention, independent Splunk searches, or existing ES content.
  • Duplicates ingestion/storage cost and requires schema parity in two analytics planes.
  • Only OCI Logging sources in the connector filter follow this route.

02 Log Analytics source of truth

Collect OCI and on-premises telemetry into Log Analytics, recreate the prioritized Splunk rules in LAQL, emit governed metrics, and invoke a bounded exporter that re-queries matching evidence and posts an enriched HEC envelope.

flowchart TB S["OCI + on-prem sources"] --> LA["OCI Log Analytics\nsource of truth"] LA --> SS["Saved search + detection rule"] SS --> M["Monitoring metric"] M --> A["Alarm + Notifications"] A --> F["Evidence Export Function"] F -->|"bounded LA query"| LA F --> V["Vault token · checkpoint · DLQ"] F --> H["Splunk HEC\nenriched detection index"]
  • Preserves OCI parsing, correlation, dashboards, and tuning as the primary control plane.
  • Forwards evidence and context, not an uncontrolled second copy of every event.
  • Requires a tested export worker because detection rules post metrics—not log records.
Non-negotiable boundary. A Log Analytics ingest-time or scheduled detection posts a metric to OCI Monitoring. The alarm payload is a trigger and correlation hint. The exporter must use a registered saved-search query, bounded lookback, dimensions, and watermark to retrieve the actual evidence before sending it to Splunk.

Option 2 · evidence export control plane

Designed for replay safety, least privilege, and observable failure rather than fire-and-forget delivery.

sequenceDiagram autonumber participant S as Source / Management Agent participant L as Log Analytics participant D as Saved Search + Detection participant M as Monitoring / Alarm participant N as Notifications participant F as Export Function participant V as Vault + State / DLQ participant H as Splunk HEC S-->>L: Parsed event with stable source and entity fields L->>D: Scheduled bounded query D-->>M: Numeric metric + <=3 dimensions M-->>N: Alarm transition with detection identity N-->>F: At-least-once trigger F->>V: Read HEC secret and checkpoint F->>L: Query [watermark-overlap, alarm end] with rule dimensions L-->>F: Matching evidence rows F->>F: Normalize, redact, batch, hash event IDs F->>H: HEC batch with idempotency metadata alt HEC 2xx F->>V: Advance checkpoint and write receipt else timeout / 429 / 5xx F->>V: Retry with backoff, then DLQ without advancing watermark else 4xx / schema failure F->>V: Quarantine and emit operational metric end

Component ownership

The detections repository owns content contracts; the Splunk repository owns the raw transport and Splunk-side application.

Detection repository

  • Splunk SPL provenance and priority registry
  • LAQL saved searches and detection specs
  • Evidence-envelope schema and synthetic fixtures
  • Exporter Function source, Terraform module, tests, runbook, diagrams

oci-splunk

  • Logging → Streaming raw fan-out
  • SOC4Kafka / Kafka Connect consumer
  • Managed or existing Splunk HEC
  • Splunk app, indexes, CIM, dashboards, saved searches, transport verification

Customer-owned controls

  • Source allow-list and retention tier
  • Splunk HEC endpoint/index/token
  • Vault, network egress, IAM, quotas
  • Alarm thresholds, notification destinations, acceptance and rollback
